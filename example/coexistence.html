Every button Bootstrap documents

Solid, outline, sizes and states — the whole matrix from the docs. Two of these are worth watching: .btn-light and .btn-dark are not status colours, so they are not in the adapter's role map. They used to compile from Sass and freeze there, ignoring every theme switch; they are now bound to the surface and inverted tokens.

What to watch:
  • Toggle theme — every control in both columns changes together. Bootstrap follows because the adapter repoints --bs-* at the semantic tokens; the right column follows because it reads them directly.
  • Rewrite one semantic token — this button changes --app-bg-action on :root and nothing else. One declaration moves both vocabularies. That single-token propagation is the entire promise of the adapter, made visible.
  • Danger stays red through all of it. Bootstrap expresses variants by setting --bs-btn-bg per class, so the adapter binds the design system on background-color rather than on --bs-btn-bg — binding on the variable would beat every variant and collapse all three buttons into one colour.
  • Compact density moves --app-space-unit alone. Every spacing step is a calc() against it, so one variable rescales the whole subtree.
