MVP fills buttons from --color-link — one variable doing two jobs, link colour and button background. Hover was filter: brightness(1.2); the adapter sets that multiplier to 1 and binds the hover colour from the token instead.

What this page is testing:
  • Interaction as a filter, not a colour. The one shape none of the other seven libraries has. The standing rule is to leave a library's character alone where the design system has no token — but here it does have one, and a brightness multiplier does the opposite of what the brand theme asked for, since its hover goes one step darker.
  • A filter breaks the pair invariant by construction. It moves the background without the foreground, and it does so invisibly: the build-time contrast check measures token pairs and cannot see a runtime filter. That is why this is the one library trait the adapter overrides rather than preserves.
  • Decomposition again, in miniature. --box-shadow is geometry only, composed at the use site with a separate colour variable. Pointing it at a complete shadow token would emit two shadows concatenated. It stays MVP's — the same problem as Bulma's HSL channels, one variable wide.
  • No theme switch of its own. MVP's dark mode is a media query gated on an attribute, with no manual toggle. The buttons above give it one it never shipped with, without touching the library.
