DS Hot Tone with Bootstrap · phase 1

A product design system built on this foundation. The palette is warm throughout — surfaces carry a paper tint rather than neutral grey — and the vocabulary is four button patterns, not the several hundred Bootstrap makes available.

Phase 1 means there is no abstraction yet: the ledger records the decisions and the agent both applies and enforces them, but the markup still carries library classes. Nothing has been written in SCSS or wrapped in a component. This is the cheapest possible closed vocabulary.

What the ledger refuses

These are not rendered, because they are not in the vocabulary. Each refusal in patterns.json carries a reason and an alternative — a rule with neither gets bypassed by the next person in a hurry.

Asked forWhy notUse
btn-successStatus colours report an outcome; a button proposes an action that has not happened. A green Save reads as “saved”.primary
btn-warningAmber is feedback, and in a warm palette it is nearly indistinguishable from primary.destructive
btn-infoBlue is outside this brand's palette; it reads as a foreign element.secondary
btn-light, btn-darkAbsolute palette names do not invert with a theme.secondary

Where this goes next

Phase 2 promotes a pattern out of raw when it earns it: three or more library classes at the call site, a structural divergence from Bootstrap, or a mistake repeated. secondary is the likely first candidate — it already composes two classes and this product wants a heavier border than Bootstrap draws.
