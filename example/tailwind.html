Buttons, with no library at all

What this page is testing:
  • A bridge is not an adapter. An adapter translates a library's vocabulary into ours, one way. This runs the other direction and publishes ours as utilities. Tailwind needs no adapter because it has no theme vocabulary of its own to translate.
  • inline is the whole mechanism. Plain @theme would resolve the value at build time and publish a second variable, so a theme switch would not move the utility. @theme inline keeps the reference and publishes nothing — the utilities above follow the theme at zero extra bytes.
  • The bridge is colour-only, on purpose. Spacing, radius and typography come from Tailwind's own scales, which already read the same layer 1 values. Re-bridging them would generate a second family of classes that do the same thing.
  • Anything unbridged is still reachable. Hover and status-subtle colours use bg-[var(--app-…)]. That is still layer 2, so it is inside the rule, not around it — and it is the signal to watch: if one of these gets written often, bridge it.
