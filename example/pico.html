What this page is testing:
  • A classless library needs no variant binding. Bootstrap expresses variants as classes that set custom properties, so its adapter re-binds each one. Pico expresses them as element selectors, so there is nothing to re-bind — the adapter is root variables and nothing else.
  • Pico owns data-theme too. It ships [data-theme=light] and [data-theme=dark] blocks declaring the same variables this adapter drives. That is an attribute collision, resolved purely by layer order. Under brand neither of Pico's blocks matches at all, and the result is the same — which is the point of not special-casing theme names.
  • The library had to be layered. Pico ships unlayered, and unlayered CSS beats every cascade layer. pico-entry.css exists solely to wrap it in @layer vendor.
  • Pico splits text from background per intent. --pico-primary colours links while --pico-primary-background fills buttons. Layer 2 already models that split as fg-action and bg-action, so the mapping is one-to-one rather than a compromise.
